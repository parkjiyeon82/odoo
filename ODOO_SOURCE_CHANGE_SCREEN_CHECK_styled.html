소스를 변경하고 화면에서 확인하려면 어떻게 해야해?

Docker 기반 Odoo 개발 환경에서 변경 내용을 빠르게 확인하는 실전 루틴

1. 기본 원칙

  • 코드를 저장해도 모든 변경이 자동 반영되지는 않습니다.
  • 파일 종류에 따라 새로고침 / 서버 재시작 / 모듈 업데이트(-u)가 필요합니다.
핵심: Python 변경은 재시작, XML/보안/데이터 변경은 모듈 업데이트가 안전합니다.

2. 가장 많이 쓰는 확인 루틴 (PowerShell)

cd C:\workspace\odoo-docker
docker compose up -d
docker compose logs -f odoo
  1. Cursor에서 코드 수정
  2. 아래 변경 유형에 맞는 명령 실행
  3. 브라우저에서 http://localhost:8069 새로고침

3. 변경 유형별 반영 방법

A) Python 코드 변경 (models/*.py, controllers/*.py)

서버 재시작이 필요합니다.

docker compose restart odoo

B) XML/View/Security/Data/Manifest 변경

모듈 업데이트 후 재시작 권장:

docker compose exec odoo odoo -c /etc/odoo/odoo.conf -d odoo18_dev -u <module_name> --stop-after-init
docker compose restart odoo

C) JS/CSS/SCSS 변경

  • URL에 ?debug=assets를 붙여 접속
  • Ctrl + F5 강력 새로고침
  • 필요하면 B 방식(모듈 업데이트)도 함께 실행

4. 모듈명은 무엇을 넣어야 하나요?

-u <module_name>의 모듈명은 보통 폴더명(기술명)입니다.

# 예시 폴더
C:\workspace\odoo-docker\custom-addons\my_partner_ext\__manifest__.py

# 사용해야 할 모듈명
my_partner_ext

5. 안 바뀔 때 점검 체크리스트

  • 로그 확인: docker compose logs -f odoo
  • DB 이름 확인: -d odoo18_dev가 실제 DB와 일치하는지
  • 모듈명 확인: 폴더명/manifest 존재 여부
  • 브라우저 캐시 제거: Ctrl + F5

6. 빠른 명령 요약

# 서버 재시작
docker compose restart odoo

# 모듈 업데이트 + 재시작
docker compose exec odoo odoo -c /etc/odoo/odoo.conf -d odoo18_dev -u <module_name> --stop-after-init
docker compose restart odoo
